# MYCELIUM AI — AUTOPILOT ROADMAP V1

## 0. Doel

Maak van de huidige Mycelium AI + INVENTory codebase een daadwerkelijk bruikbaar systeem waarin:

* de bestaande backend-functionaliteit bereikbaar is via UI;
* Research → Mission → Node execution daadwerkelijk end-to-end werkt;
* Mycelium als persoonlijke AI/coördinator bruikbaar wordt;
* INVENTory als wereldmodel bruikbaar wordt;
* projecten, research, missions, objects en relaties samenkomen;
* de game/living-world laag uiteindelijk een Terraria/Ori-achtige interactieve interface krijgt;
* agents zelfstandig verder kunnen bouwen zonder voortdurende menselijke begeleiding.

De agents moeten niet proberen alles tegelijk te bouwen.

**Werk altijd vanuit de huidige code als source of truth.**

---

# 1. ABSOLUTE REGELS

## 1.1 Geen destructieve refactors

Agents mogen:

* nieuwe bestanden toevoegen;
* bestaande functies uitbreiden;
* kleine gerichte wijzigingen maken;
* tests toevoegen;
* UI koppelingen toevoegen;
* adapters bouwen.

Agents mogen NIET zonder expliciete reden:

* bestaande subsystemen volledig herschrijven;
* databases verwijderen;
* bestaande API's breken;
* bestaande veiligheidslagen omzeilen;
* authentication/approval gates verwijderen;
* willekeurige shell/RCE-functionaliteit introduceren;
* productiecode vervangen omdat een agent het "mooier" vindt.

---

## 1.2 Bestaande veiligheidsarchitectuur blijft leidend

Bestaande gates blijven intact:

* human approval;
* `YES` approval;
* mission status gates;
* lease;
* claim;
* attempt limits;
* ownership;
* capability checks;
* provenance;
* dispatchable kinds;
* fail-closed gedrag.

Agents mogen deze mechanismen verbeteren, maar nooit omzeilen.

---

## 1.3 Elke agent werkt in kleine verticale slices

Elke opdracht moet:

1. bestaande code inspecteren;
2. één duidelijk probleem kiezen;
3. implementeren;
4. tests schrijven;
5. relevante bestaande tests draaien;
6. `git diff --check`;
7. commit maken;
8. korte changelog/reportsamenvatting schrijven.

Geen enorme ongeteste wijzigingen.

# 23. DEFINITION OF DONE

Een taak is pas DONE wanneer:

* code werkt;
* relevante tests bestaan;
* relevante tests passeren;
* bestaande tests niet breken;
* `git diff --check` pass;
* geen security gate verwijderd;
* geen bestaande API onbedoeld gebroken;
* commit gemaakt;
* changelog bijgewerkt.

# 24. NACHTMODUS

Autonomous mode:

```text
while work_available:

    select_highest_priority_safe_task()

    inspect_current_code()

    implement_small_slice()

    run_targeted_tests()

    run_regression_tests()

    if pass:
        git diff --check
        commit
        update_work_queue()

    if fail:
        revert_unwanted_changes
        document_failure
        choose_next_independent_task()
```

Agents moeten **niet wachten op menselijke bevestiging voor normale codewijzigingen**.

Wel blokkeren bij:

* destructive migration;
* data deletion;
* security downgrade;
* approval bypass;
* public deployment;
* secrets;
* irreversible external actions.
